# HANDOFF

## Состояние

**v109 — пометка на удаление документов на вкладке бренда заявки.**
Активная цепочка не менялась: `request → calculation → invoice`.
Единственный признак "к удалению" — `is_deleted` (поле
`Calculation.status` с вариантом "К удалению" УДАЛЕНО целиком).

## Сделано в этой сессии

1. Список калькуляций и список счетов слота показывают ВСЕ документы,
   включая помеченные на удаление (раньше: калькуляции фильтровались по
   `status=="active"`, счета — по `is_deleted==False`).
2. Один ряд чекбоксов вместо двух (колонка копирования убрана;
   `brandCalcCopyTarget`/`brandInvoiceCopyTarget` удалены). Выбор —
   множество: `brandCalcSelected` / новый `brandInvoiceSelected`.
3. "Скопіювати" активна только при РОВНО одном выделенном (и для
   калькуляций, и для счетов).
4. Новая кнопка "Видалення" (в обоих списках) — инверсия `is_deleted`
   у выделенных: помеченный → снят, непомеченный → помечен. Action
   `toggle_brand_deleted` (payload `{kind, ids}`), атомарно, возвращает
   свежие `brand_slot_N_calcs/_invoices`.
5. Серый бейдж "удаление" (`.badge-deleted`, по образцу `.badge-frozen`),
   строка помеченного приглушена (`.row-deleted`).
6. "Створити рахунок": помеченные на удаление не попадают в счёт НИКОГДА
   (фронт не шлёт их id, сервер фильтрует повторно; если выделены только
   помеченные — кнопка disabled / сервер 422). Если среди выделенных есть
   и помеченные — `confirm` перед созданием.
7. "Обновить цены" пропускает помеченные на удаление.
8. Убрано `Calculation.status`: модель, поле формы, копирование, список.
   Миграция Postgres: `_migrate_calculation_status_to_is_deleted()`
   переносит `status='delete_pending'` → `is_deleted=true`, затем
   `_drop_obsolete_columns()` дропает колонку `calculation.status`.
9. `APP_VERSION` v108 → v109; `entity_registry.md` обновлён.

Проверено локально (SQLite, TestClient, `PRAGMA foreign_keys=ON`):
10 сценариев (список показывает все, инверсия, смешанная инверсия, счёт
без помеченных, 422 при одних помеченных, пометка счетов, валидация
payload, копия помеченной без пометки, "Обновить цены", рендер страниц);
`node --check` генерируемого JS на 4 страницах.
