# HANDOFF

## Состояние

**v91 — печатная форма счёта (PDF) готова и подключена. Готово к
заливке в `ai-updates/`.**

zayavka -> calculation -> specification -> invoice (счёт-фактура).
Кнопка «Скачать PDF» — на карточке invoice, рядом с «Обновить»/
«Отвязать от спецификации». Печатная форма (макет утверждён по
образцу СФ-0000040, две итерации правок 2026-08-31) реализована через
reportlab (чистый Python, без системных зависимостей — WeasyPrint
сознательно НЕ выбран из-за риска рассинхронизации Docker-окружения
на Railway/Nixpacks).

**Новое поле `Calculation.unit_id`** (FK -> Unit) — единица измерения
ГОТОВОГО ИЗДЕЛИЯ целиком (не материала состава), нужна для колонки
«Од.» в счёте. По умолчанию подставляется запись Unit с
name="послуга" через новый универсальный примитив движка
`TableConfig.before_create_hook` (симметричный уже существовавшему
`before_update_hook`, вызывается в `create_item` ДО `model(**data)`,
получает и возвращает dict, а не instance — на этом шаге ещё нет
созданного объекта). Поле показано в форме калькуляции на вкладке
«Основное», рядом с «Полное название». Мигрировано в
`_ensure_is_deleted_columns()` как `INTEGER NULL` (та же логика, что
у `material.unit_id`, v63) — обязательно, т.к. таблица `calculation`
уже существует на Railway.

**Новый модуль `app/invoice_print/`**:
- `data.py` — `build_invoice_print_data()`: единая точка сборки
  данных счёта (Invoice → Firm/Client/InvoiceItem → цепочка
  `InvoiceItem.specification_item_id` → `SpecificationItem.
  calculation_id` → `Calculation.unit_id` → `Unit.name` для единицы
  измерения строки). Возвращает плоский `InvoicePrintData` —
  переиспользуется ЛЮБЫМ будущим экспортёром (Excel запрошен
  Вахтангом, ещё не начат), расчёт сумм/реквизитов не должен
  дублироваться между builder'ами.
- `amount_in_words.py` — сумма прописью на украинском (гривні/
  копійки) с согласованием родов (гривня — женский род, тройка
  единиц перед ней склоняется в женском: «одна», «дві», а не «один»,
  «два»; тысячи — всегда женский род независимо от рода следующего
  слова). Сверено на реальном образце СФ-0000040 (105532.44 → «Сто
  п'ять тисяч п'ятсот тридцять дві гривні 44 копійки» — совпадает).
- `pdf_builder.py` — сборка PDF (DejaVuSans, файлы шрифтов в
  `app/invoice_print/fonts/`, НЕ системные — не зависит от хоста).
  Макет: рамка «Увага!» по центру сверху с отступом; подчёркнутые
  метки «Постачальник»/«Одержувач»/«Платник»; итоги «Разом без ПДВ»/
  «ПДВ»/«Всього з ПДВ» — последние 3 строки ОСНОВНОЙ таблицы позиций
  (не отдельная таблица), с общей рамкой вокруг колонки суммы.
- `router.py` — `GET /invoice-print/{invoice_id}/pdf`, отдаёт готовый
  PDF как `attachment`. Зарегистрирован в `main.py` (`register_
  invoice_print`), тот же паттерн, что `documents_chain`.

Кнопка «Скачать PDF» — `ActionButton(client_side=True)`, JS-функция
`download_invoice_pdf` в `CLIENT_ACTIONS` (page.py) делает
`window.open(...)`, ничего не подмешивает в `editing`. Требует уже
сохранённой записи (id) — печатная форма читает InvoiceItem из БД, не
из ещё не сохранённой формы.

**Пока НЕ реализовано (сознательно, без явного запроса)**:
«Виписав(ла)» и «Рахунок дійсний до сплати до» печатаются как пустые
строки для заполнения от руки — в моделях Invoice/Firm нет полей под
эти данные, не обсуждалось.

## Сделано в этой сессии

1. `TableConfig.before_create_hook` — новый универсальный примитив
   движка (`config.py` + `engine/api.py::create_item`).
2. `Calculation.unit_id` (модель, миграция, форма, дефолт через хук
   `_default_calculation_unit_id` в `tables.py`).
3. `app/invoice_print/` — полный модуль (data/amount_in_words/
   pdf_builder/router), `reportlab` добавлен в `requirements.txt`.
4. Кнопка «Скачать PDF» на карточке invoice.
5. Макет PDF утверждён Вахтангом после 2 итераций правок (сверка с
   реальным сканом СФ-0000040, приложенным в чат).
6. Сквозной smoke-тест через `TestClient` (`PRAGMA foreign_keys=ON`):
   unit → client → firm (+ set_default) → request → 2×calculation
   (дефолтный и явный unit_id) → build_specification_1 →
   build_invoice → GET .../pdf — всё зелёное, суммы/НДС/пропись
   совпадают с ручным расчётом.

## Открыто

- **Excel-вариант счёта** — прямо запрошен Вахтангом («нужно учесть,
  что нужно будет ещё экселевский вариант счёта»), НЕ начат. Данные
  уже готовы к переиспользованию через `app/invoice_print/data.py::
  build_invoice_print_data()` — новому `xlsx_builder.py` останется
  только рисовать, не пересчитывать.
- **«Виписав(ла)» и «Рахунок дійсний до сплати до»** — пустые строки
  для заполнения от руки. Обсудить, нужны ли реальные поля (ФИО
  подписанта, срок действия счёта) в моделях Invoice/Firm.
- **Единица измерения на старых калькуляциях** — `unit_id = NULL` для
  записей, созданных до v91 (та же логика, что у `material.unit_id`,
  v63) — при печати счёта колонка «Од.» для них будет пустой, пока
  не поправить вручную через форму калькуляции.
- **PDF живьём на Railway/Postgres** — пока НЕ проверено (только в
  контейнере). reportlab — чистый Python без системных зависимостей,
  риск ниже, чем был бы у WeasyPrint, но живая проверка после деплоя
  всё равно нужна.
- Пункты 2–4 дорожной карты (ценообразование/актуализация цен,
  «перепроведение» остальных документов, Excel/PDF-экспорт как общий
  пункт) — Excel по счёту теперь имеет частичный задел (см. выше),
  остальное не начато.
- Рефакторинг `enginePage()` — по-прежнему сознательно отложен.
