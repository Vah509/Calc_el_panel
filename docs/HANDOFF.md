# HANDOFF

## Состояние

**v96 — Сессия 1 плана "Перепроведение" (модель данных).**
Добавлены два новых поля на уже существующие в проде таблицы:
`InvoiceItem.calculation_id` (FK на Calculation, nullable, НЕ
бэкфиллится) и `Invoice.is_frozen` (bool, default False). Это первый
шаг многосессионного плана, полностью описанного в
`docs/HANDOFF_reprovodenie.md` — переход от документооборота
Request→Calculation→Specification→Invoice к прямому
Request→(калькуляции по брендам с чекбоксами)→Invoice, с постепенным
выводом Specification из цепочки.

Никакой бизнес-логики/UI в этой сессии не менялось — только модель
данных и обязательная миграция колонок для Postgres. Кнопки, хендлеры,
merge-логика по `calculation_id`, переключение `is_frozen` через UI —
следующие сессии (2–5 по плану).

## Сделано в этой сессии

1. **`app/models/invoice_item.py`** — добавлено поле `calculation_id`
   (FK→calculation.id, nullable=True). Подробный комментарий в файле
   объясняет: старые строки (созданные через путь Specification) не
   трогаем, остаются NULL; новые строки (сессия 4) будут заполнять его
   сразу; бэкфилл старых строк отложен до финального удаления
   Specification/SpecificationItem — решение Вахтанга 2026-09-03.
2. **`app/models/invoice.py`** — добавлено поле `is_frozen`
   (bool, default False). Переключается вручную кнопкой "Заморозить"
   (не автоматически). Логика при повторном "Создать счёт" на том же
   наборе калькуляций: `is_frozen=False` → обновление на месте,
   `is_frozen=True` или счёта ещё нет → новый документ.
3. **`app/database.py`, `_ensure_is_deleted_columns()`** — обе новые
   колонки (`invoiceitem.calculation_id` INTEGER NULL,
   `invoice.is_frozen` BOOLEAN NOT NULL DEFAULT false) добавлены в
   миграционный список В ТОМ ЖЕ коммите, что и модели — критический
   паттерн проекта (иначе прод падает на первом INSERT после деплоя).
4. **`app/version.py`** — `APP_VERSION` v95 → v96.
5. **`entity_registry.md`** — обновлены разделы таблиц `invoice`
   (добавлен `is_frozen`) и `invoice_item` (добавлен `calculation_id`,
   пометка на `specification_item_id` как "уходящий путь"), обновлена
   шапка версии/даты документа.
6. Проверено локально (SQLite, `TestClient` context manager):
   `/health` → 200, smoke-тест всех основных страниц документооборота
   (`/request-v2`, `/calculation-v2`, `/specification-v2`,
   `/invoice-v2`, `/material-v2`) → 200, прямая вставка `Invoice` и
   `InvoiceItem` через ORM с новыми полями отрабатывает без ошибок
   (`is_frozen=False` по умолчанию, `calculation_id=None` принимается).
