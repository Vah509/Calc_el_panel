# HANDOFF

## Состояние

**v97 — Сессия 2 плана "Перепроведение" (UI вкладок бренда + список
калькуляций с чекбоксами).**
Заявка (`request`) получила вкладки формы: "Основное" (номер/дата/
клиенты/заметка) и по одной на каждый брендовый слот ("Вариант 1/2/3").
На каждой вкладке слота — под полем бренда — новый read-only список
активных калькуляций этого слота (номер/название/сумма/дата) с
чекбоксом в каждой строке и кнопкой "Обновить список".

Чисто фронтенд/список, как и было запланировано — **никаких изменений
модели данных, никакого создания/обновления документов**. Чекбоксы
живут только в браузере (сбрасываются при каждом открытии формы),
ничего не пишут в БД. Их отмеченный набор начнёт на что-то влиять
(создание/обновление счёта, точечный пересчёт цен) в сессиях 3–4
плана "Перепроведение" (см. `docs/HANDOFF_reprovodenie.md`).

## Сделано в этой сессии

1. **Согласован открытый вопрос №4 плана** (в начале сессии, до
   кода): колонки списка калькуляций — номер + название + сумма +
   дата; сортировка по умолчанию — по дате, новые сверху.
2. **`app/engine/config.py`** — новый примитив `TableConfig`:
   `brand_slot_calc_tabs` (список кортежей tab_name/slot_number/
   calcs_field), `brand_slot_calc_refresh_action`,
   `brand_slot_calc_columns`. Общий по духу с уже существующими
   `materials_tab`/`readonly_items_tab`, но отдельный — концептуально
   не про CRUD дочерних строк, а про группировку по номеру слота и
   клиентские чекбоксы.
3. **`app/engine/tables.py`**:
   - Новый обработчик `_refresh_brand_calculations_handler` — собирает
     АКТИВНЫЕ (`status="active"`) калькуляции заявки отдельно для всех
     трёх `brand_slot` сразу, сортировка `document_date desc,
     document_time desc`. Возвращает `{"brand_slot_1_calcs": [...],
     "brand_slot_2_calcs": [...], "brand_slot_3_calcs": [...]}`.
   - Зарегистрирован в `action_handlers` под именем
     `refresh_brand_calculations` — используется И как
     `open_edit_action` (автозагрузка при каждом открытии формы
     заявки, без клика человека), И как явное действие кнопки
     "Обновить список" на каждой из трёх вкладок (один обработчик на
     все три вкладки сразу).
   - `request_table` получил `form_tabs=["Основное", "Вариант 1",
     "Вариант 2", "Вариант 3"]`, все существующие поля разнесены по
     `tab=`. Старые `row_actions` "Спецификация"/"Пересчитать" у
     каждого `brand_slot_N_id` НЕ тронуты — путь через спецификацию
     продолжает работать как раньше (уберётся в сессии 6).
4. **`app/engine/page.py`**:
   - HTML-блок списка калькуляций с чекбоксом внутри цикла вкладок
     формы (`{% for bsc_tab, bsc_slot, bsc_field in
     config.brand_slot_calc_tabs %}`), переиспользует
     `.readonly-items-table` целиком.
   - JS-state `brandCalcSelected` (`{1: Set, 2: Set, 3: Set}`) +
     методы `brandCalcChecked()`/`brandCalcToggle()` — чисто
     клиентское состояние чекбоксов, сбрасывается в `openCreate()` и
     `openEdit()`.
5. **`app/static/style.css`** — стиль узкой колонки чекбокса
   (`.brand-calc-table`), переиспользует остальной вид
   `.readonly-items-table`.
6. **`app/version.py`** — `APP_VERSION` v96 → v97.
7. **`entity_registry.md`** — раздел таблицы `request` дополнен
   описанием новых вкладок формы и примитива `brand_slot_calc_tabs`,
   обновлена шапка версии/даты документа.
8. Проверено локально (SQLite, `TestClient` context manager,
   `test_session2.py`, удалён перед архивацией):
   - `/health`, smoke всех основных страниц документооборота → 200;
   - `POST .../actions/refresh_brand_calculations` на сохранённой
     заявке с калькуляциями на разных слотах и разных статусах —
     корректно группирует по слоту, фильтрует `delete_pending`,
     возвращает нужные поля;
   - 404 на несуществующей заявке;
   - `/request-v2/new` и `/request-v2/{id}` (форма) рендерят
     `form-tabs-bar`, кнопку "Обновить список", три вкладки
     "Вариант 1/2/3".
