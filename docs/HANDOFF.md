# HANDOFF

## Состояние

**v74 — клик по документу в "Цепочке документов" открывает его карточку
на родной странице, чекбокс работает независимо от клика по строке.**

Раньше (v73) клик по ЛЮБОЙ части строки в журнале цепочки переключал
чекбокс выделения. Теперь: чекбокс переключается ТОЛЬКО кликом по
себе (`@click.stop` на ячейке), а клик по остальной части строки
(`openDocument()`) переходит на родную страницу этого типа документа
(`/request-v2` или `/calculation-v2`) с параметрами
`?open_id={id}&chain_request_id={id заявки}` — полная перезагрузка,
тот же принцип, что уже использовался для `?from_request=`
(createChildDocument, v62).

Целевая страница (универсально, через `enginePage()` — не хардкод
под конкретную таблицу) подхватывает `?open_id=` в `maybeOpenById()`:
ищет запись среди уже загруженного списка, если не находит — точечно
догружает через НОВЫЙ эндпоинт `GET /api/{key}/{item_id}` (раньше
такого не было, только list), и открывает её тем же `openEdit()`,
которым открывается обычный клик по строке в родном журнале — форма
со всеми вкладками/особенностями конкретной таблицы работает без
дублирования логики.

Если пришли из цепочки (`?chain_request_id=` присутствовал), в
topbar целевой страницы появляется кнопка "← К цепочке"
(`chainReturnUrl`), ведущая обратно на `/documents-chain?request_id=...`.
Если пришли обычным способом — кнопки нет.

`TableConfig` получил новое поле `own_page_url` (config.py) — URL
собственной страницы типа документа, заполнено у `request_table`
(`/request-v2`) и `calculation_table` (`/calculation-v2`). API
цепочки (`app/documents_chain/api.py`) отдаёт его в каждой группе,
фронт (`app/documents_chain/page.py`) использует для перехода.
Справочники (material, brand и т.п.) этого поля не имеют — им
открытие через цепочку не нужно.

**Отклонение от первоначального плана:** обсуждали модалку прямо на
странице цепочки, но т.к. форма редактирования (`enginePage()`)
жёстко завязана на один `CONFIG` на страницу (form_tabs/
materials_tab/kits_tab/computed_pairs и т.д.), встраивание чужой формы
в универсальную страницу цепочки означало бы дублирование сложной
логики или iframe-в-модалке с обменом состоянием — решили вместо
этого переиспользовать уже существующие родные страницы документов
через переход с `?open_id=`, т.к. в проекте и так нет SPA-переходов
нигде, полная перезагрузка — принятый паттерн.

## Сделано в этой сессии

- `app/engine/api.py` — новый `GET /{item_id}` (одиночная запись по
  id) для любой таблицы движка, вставлен перед `PUT /{item_id}`
- `app/engine/config.py` — `TableConfig.own_page_url` (новое поле)
- `app/engine/tables.py` — `own_page_url` задан у request и calculation
- `app/engine/page.py`:
  - `chainReturnUrl` state + кнопка "← К цепочке" в topbar (видна
    только когда задан)
  - `maybeOpenById()` — подхватывает `?open_id=`/`?chain_request_id=`,
    находит/догружает запись, открывает `openEdit()`
  - вызов `maybeOpenById()` добавлен в `init()` после `maybeOpenFromRequest()`
- `app/documents_chain/api.py` — `own_page_url` добавлен в `_group_meta()`
- `app/documents_chain/page.py`:
  - клик по строке → `openDocument(group, item)` (переход на
    `own_page_url` с параметрами), чекбокс — `@click.stop`, свой `@change`
  - если у группы нет `own_page_url` — понятная ошибка вместо перехода
- Протестировано через `TestClient`: `own_page_url` приходит в API
  цепочки для обеих групп, `/documents-chain` содержит `openDocument`,
  `/request-v2`/`/calculation-v2` с `?open_id=` рендерятся и содержат
  нужную разводку, `GET /api/{key}/{id}` работает для обоих типов и
  отдаёт 404 для несуществующего id, старый `?from_request=`
  сценарий не сломан, `material-v2` (без `own_page_url`) не затронут,
  обычная загрузка списков работает
- Новых полей моделей НЕ добавлялось — миграций не требуется

## Открыто

- Не проверено на реальном устройстве (только TestClient/SQLite)
- Кнопка "← К цепочке" сейчас появляется на ЛЮБОЙ странице движка при
  наличии `?chain_request_id=` в URL — по задумке это нормально
  (универсальный механизм), но визуально не проверено, как выглядит
  рядом с "+ Новая запись" на разных таблицах
- `specification`/`invoice` по-прежнему не реализованы — когда
  появятся, помимо `ChainLink` в `document_chain.py` понадобится
  также задать им `own_page_url` в своём `TableConfig`, иначе клик по
  строке в цепочке покажет "не задана страница" вместо перехода
