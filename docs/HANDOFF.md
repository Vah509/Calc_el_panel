## Сделано в этой сессии

1. **Выпадающее меню на ПК закрывалось раньше времени** —
   `app/static/style.css`: у `.nav-dropdown-panel` `margin-top: 4px`
   заменён на `padding-top: 4px` (зазор теперь внутри hover-зоны, а
   не снаружи неё), визуальное оформление (фон/border/тень)
   перенесено во вложенный `.nav-dropdown-panel-inner`.
   `app/templates/base.html` — содержимое `.nav-dropdown-panel`
   обёрнуто в `<div class="nav-dropdown-panel-inner">`. Мобильный
   `:focus-within`-сценарий не тронут.
2. **Индикатор "требует сохранения" / "сохранено"** — в
   `app/engine/page.py`: `formSnapshot`/`isDirty` в состоянии
   Alpine-компонента, `takeFormSnapshot()`, `$watch('editing', ...)`
   в `init()`. Снимок берётся в конце `openCreate()` (после
   подстановки автономера) и в конце `openEdit()` (после
   `radioActions`/`CONFIG.openEditAction`, чтобы автоподгрузка данных
   при открытии формы не считалась правкой). Индикатор в
   `modal-header` (только для обычных форм-документов, не
   items_modal-справочников kit_group/kit_section) + CSS
   `.form-dirty-indicator` в `style.css`.
3. **Сохранение без закрытия формы** — в `app/engine/page.py`:
   `save()` больше не закрывает форму — только отправляет данные
   (POST/PUT), мерджит ответ сервера в `editing` (важно: подхватывает
   `id`, присвоенный сервером при создании — иначе повторное
   `save()` снова ушло бы POST'ом и создало дубликат) и обновляет
   `formSnapshot`. Новая `saveAndClose()` — делает `save()`, при
   успехе закрывает форму (старое поведение). `close()` не изменился
   (закрывает без сохранения). Кнопка "Сохранить и закрыть" добавлена
   в оба `modal-footer-right` блока (обычные документы и
   hierarchy-формы kit_group/kit_section).
4. **`app/version.py`** — `APP_VERSION` v105 → v106.
5. **`entity_registry.md`** — добавлен подраздел "Универсальная форма
   движка: сохранение и индикатор состояния (v106)" в разделе 1
   (Инфраструктура), шапка файла актуализирована.
6. Проверено локально (SQLite, `TestClient` context manager,
   `PRAGMA foreign_keys=ON`):
   - Все основные страницы (`/request-v2`, `/calculation-v2`,
     `/invoice-v2`, справочники, `/processors`, `/documents-chain`,
     `/`) — 200, разметка `nav-dropdown-panel-inner`,
     `form-dirty-indicator`, кнопка `saveAndClose()` присутствуют в
     отрендеренном HTML (в т.ч. на hierarchy-таблице `kit_group-v2`).
   - Сквозной сценарий "save без закрытия" на СЕРВЕРНОЙ части (то,
     что делает новый `save()`: POST → merge id → PUT) — на трёх
     типах документов: `request` (обязательный `client_id`),
     `calculation`, `invoice` (создан напрямую через сессию, т.к.
     `allow_create=False`). Во всех трёх случаях повторное
     сохранение идёт PUT'ом по уже присвоенному id и НЕ создаёт
     дубликат записи.
   - JS-код внутри `<script>` (весь `enginePage()`) проверен на
     синтаксис через `node --check` после подстановки заглушки вместо
     `{{ config_json | safe }}` — ошибок нет.
   - Баланс тегов Jinja (`{% if/for/macro %}` ↔
     `{% endif/endfor/endmacro %}`) в `page.py` — 93/93, сходится.
   - Ручная проверка меню (наведение курсора по диагонали) НЕ
     выполнялась — только структурная/CSS-проверка (нет браузера в
     этой среде); визуальное поведение стоит перепроверить на
     реальном устройстве после деплоя.
